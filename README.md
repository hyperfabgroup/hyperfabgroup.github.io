# hyperfabgroup.github.io

صفحه‌ی معرفی رسمی **هایپرفب** (HyperFab) روی GitHub Pages، به فارسی و انگلیسی.
نشانی اصلی: https://hyperfabgroup.github.io — نشانی قدیمی https://hyperfab-ir.github.io هم باز می‌ماند و canonical صفحه‌هایش به نشانی اصلی اشاره می‌کند (کروم نشانی قدیمی را به‌خاطر شباهت به hyperfab.ir «مشکوک» نشان می‌داد).
سایت اصلی و ثبت سفارش: https://hyperfab.ir

هدف این سایت این است که موتورهای جست‌وجو و دستیارهای هوش مصنوعی (ChatGPT، Claude، Perplexity، Gemini و …)
که به سرورهای داخل ایران دسترسی ندارند، خدمات هایپرفب را ببینند و به hyperfab.ir ارجاع دهند.

## ساختار

| مسیر | محتوا |
|---|---|
| `/` و `/en/` | صفحه‌ی اصلی: همه‌ی خدمات، تخمین‌گر قیمت، تکه‌یاب، تیم، سؤالات متداول، تماس |
| `/price-estimator/` و `/en/price-estimator/` | تخمین‌گر آنلاین قیمت |
| `/tekeyab/` و `/en/tekeyab/` | تکه‌یاب |
| `/punching/`، `/tube-laser-cutting/`، `/injection-molding/`، `/cnc-turning/`، `/aluminium-extrusion/`، `/welding/`، `/plating-anodizing/`، `/powder-coating/` (و نسخه‌ی `/en/` هر کدام) | خدمات تولید صنعتی و تیراژی؛ سفارش تلفنی |
| `robots.txt`، `sitemap.xml`، `llms.txt`، `llms-full.txt` | راهنمای خزنده‌ها و هوش مصنوعی؛ `llms-full.txt` متن کامل همه‌ی صفحه‌ها در یک فایل است |

## ویرایش

صفحه‌های HTML دستی ویرایش نمی‌شوند؛ از روی متن‌های `tools/` ساخته می‌شوند.

1. متن فارسی را در `tools/content_fa.py` و انگلیسی را در `tools/content_en.py` ویرایش کنید.
   خدمات صنعتی در `tools/industrial_*.py` و `tools/industrial2_*.py` هستند،
   نمونه‌کارها و ویدیوهای واقعی در `tools/media.py`، و اطلاعات تماس مشترک در `tools/common.py`.
   شماره‌های تلفن در پیوندهای `tel:` و `telephone` در schema.org به قالب E.164 هستند
   (`+982177527438` و `+989962233898`؛ کلیدهای `landline_e164` و `mobile_e164` در `CONTACT`).
   راهنماها (مقاله‌های `/guides/<slug>/` و `/en/guides/<slug>/`) هر کدام یک فایل `tools/guides/g_<نام>.py` هستند
   (قالب پایین را ببینید).
2. اجرا کنید (پایتون ۳٫۱۲ یا بالاتر):

   ```bash
   python3 tools/build.py
   ```
3. کامیت و پوش کنید؛ GitHub Pages ظرف یکی دو دقیقه به‌روز می‌شود.
   فقط ریپوی `hyperfabgroup` پوش می‌شود (`git push origin main`؛ ریموت `old` همان سایت قدیمی است و نباید به آن پوش شود).
   اگر دو پوش پشت‌سرهم بفرستید، GitHub ممکن است دومی را با خطای
   «Deployment request failed … due to in progress deployment» رد کند و ایمیل خطا بفرستد.
   این خطا از خود سایت نیست: صبر کنید انتشار قبلی تمام شود، بعد یک کامیت تازه پوش کنید.

### راهنماها

هر فایل `tools/guides/g_*.py` خودکار خوانده می‌شود و یک متغیر `GUIDE = {'fa': {...}, 'en': {...}}` دارد.
کلیدهای هر زبان:

| کلید | توضیح |
|---|---|
| `slug` | نشانی صفحه، در هر دو زبان یکسان؛ حروف کوچک لاتین و عدد با `-` (مثلاً `punching-vs-laser`) |
| `title` | تیتر H1 و `<title>` (حداکثر ۶۰ نویسه؛ اگر جا باشد « \| هایپرفب» به `<title>` افزوده می‌شود) |
| `short` | (اختیاری) عنوان کوتاه برای منو، مسیر صفحه و دکمه‌ها |
| `desc` | توضیح متا؛ فارسی حداکثر ۱۵۵ و انگلیسی ۱۶۰ نویسه |
| `lead` | خلاصه‌ی پاسخ‌محور ۲ تا ۴ جمله‌ای؛ در کادر «پاسخ کوتاه» می‌آید |
| `updated` | تاریخ به‌روزرسانی `YYYY-MM-DD` (میلادی؛ در صفحه‌ی فارسی خورشیدی نمایش داده می‌شود) |
| `service` | کلید صفحه‌ی خدمت مرتبط: `punching`، `tubelaser`، `injection`، `turning`، `extrusion`، `welding`، `plating`، `coating`، `industrial`، `services`، `estimator` یا `tekeyab`. دکمه‌ی پایان راهنما به همین صفحه و به تلفن می‌رود و راهنما در ردیف «راهنماهای مرتبط» همان صفحه نمایش داده می‌شود |
| `img`، `img_alt` | (اختیاری) تصویر موجود در `assets/img/` و متن جایگزین آن |
| `keywords` | (اختیاری) کلیدواژه‌های متا |
| `sections` | فهرست بخش‌ها: `{'h': 'تیتر', 'p': ['پاراگراف', ...], 'ul': ['مورد', ...], 'table': {'head': [...], 'rows': [[...], ...]}}`؛ `ul` و `table` اختیاری‌اند. فهرست مطالب از روی `h` ساخته می‌شود |
| `faq` | فهرست `('پرسش', 'پاسخ')`؛ اگر خالی باشد بخش پرسش‌ها و FAQPage ساخته نمی‌شود |
| `related` | (اختیاری) فهرست `slug` راهنماهای مرتبط؛ slug ناموجود نادیده گرفته می‌شود |

در `p`، `ul` و خانه‌های جدول می‌شود HTML ساده (`<b>`، `<a>`) نوشت. برای پیوند به صفحه‌های همین سایت از `{home}` استفاده کنید
(مثلاً `<a href="{home}punching/">`) تا در هر دو زبان درست شود. عبارت‌های لاتین وسط متن فارسی را اگر وارونه دیده شدند
داخل `<bdi>` بگذارید. با اجرای `build.py` صفحه‌ی `/guides/`، منوی «راهنماها»، sitemap، `llms.txt` و `llms-full.txt` خودکار به‌روز
می‌شوند. اگر هیچ راهنمایی نباشد، صفحه‌ی `/guides/` و آیتم منو ساخته نمی‌شوند.

سایت قدیمی `hyperfab-ir.github.io` فقط صفحه‌های جابه‌جایی دارد که هر نشانی را به همان مسیر در
`hyperfabgroup.github.io` می‌فرستد. اگر صفحه‌ی تازه‌ای اضافه شد، `python3 tools/redirect_stubs.py <پوشه>` را
روی یک کپی از ریپوی قدیمی اجرا و آن را پوش کنید.

ظاهر از فایل `style.css` قالب وردپرس هایپرفب ۲۰٫۰ می‌آید (`assets/hyperfab.css`، بی‌تغییر).
افزوده‌های این سایت در `assets/site.css` است. اگر قالب سایت اصلی به‌روز شد، کافی است `style.css` تازه را
جای `assets/hyperfab.css` بگذارید.

## تصاویر

- `assets/img/works/` و `assets/img/real-*.jpg`: عکس‌های واقعی کار هایپرفب (از قالب سایت اصلی). روی سایت برچسب «عکس واقعی» دارند.
- `assets/img/videos/`: کاور ویدیوهای آپارات هایپرفب.
- `assets/img/arc-*.jpg`: تصاویر آرشیوی از Wikimedia Commons با مجوز آزاد. نام عکاس، مجوز و پیوند منبع هر کدام
  در `tools/images.py` ثبت است و زیر هر تصویر روی سایت نمایش داده می‌شود. هر وقت عکس واقعی از همان خدمت
  داشتید، جایگزینش کنید و ردیفش را از `tools/images.py` بردارید.
- برای هر عکس JPG/PNG بزرگ‌تر از ۱۰۰ کیلوبایت در `assets/img/` (از جمله `works/`، `arc-*.jpg` و `real-*.jpg`) یک نسخه‌ی
  `.webp` هم‌نام کنار آن هست (Pillow، کیفیت ۸۰، method 6) و فایل اصلی هم می‌ماند. برای عکس تازه:

  ```bash
  python3 -c "from PIL import Image; Image.open('assets/img/x.jpg').save('assets/img/x.webp', quality=80, method=6)"
  ```
